Roast #6 · June 4, 2026 · Singapore

Three builders put AI-generated content production, LLM evals, and the agent-versus-workflow decision under the spotlight at SGInnovate. This recap preserves the practical decisions and questions raised in the room.

Speaker 01

AI Content Pipeline

AI Content Pipeline

One input. Out comes a podcast, a blog post, images, and audio — produced in parallel. The conversation focused on how to keep partial progress when a generation step fails, and how to pick image models when cost and text-rendering both matter.

Parallel generationFail-continueImagenGPT ImageRetry logic
01

One Input, Everything in Parallel

The pipeline takes a single piece of content and fans out into a podcast, blog, images, and audio. The generation steps run in parallel rather than sequentially, collapsing overall latency down to the slowest branch.

02

Fail-Continuing, Not Fail-Fast

The room's key takeaway: never discard previous effort on failure. Continue with the partial results that already succeeded, then retry only what failed. Separating "continue what worked" from "retry what broke" keeps the pipeline resilient and cheap instead of restarting from zero.

03

Imagen vs. GPT Image

A concrete trade-off surfaced on image generation: Imagen is cheaper but does not support rendering text inside the image, while GPT Image does — or you superimpose text on top afterwards. The choice comes down to whether baked-in text is worth the extra cost per asset.

Speaker 02

LLM Evals — clear gradings

Gaurav Kumar Manek

A talk on LLM evaluation that gave the room the clearest framework of the night: a ladder of five grader types, each costing more and catching less. The rule of thumb: prefer the cheapest grader at the top of the table that reliably catches the failure mode you care about.

LLM evalsGradingTrajectory checksLLM judgeHuman review
01

The Five Grader Ladder

Five ways to grade model output, in increasing cost and decreasing coverage:

  • Exact match — compare against a canonical answer. Cheapest, but only catches deterministic failures.
  • Code execution — run the output and check the result against an assertion.
  • Trajectory checks — verify the intermediate steps and tool calls, not just the final answer.
  • LLM judge — use another model to evaluate. More flexible, harder to make reliable.
  • Human review — the most expensive and the final safety net.
02

Grade At The Top Of The Table First

Each rung down the ladder costs more and catches less. The practical takeaway: pick the cheapest grader that reliably catches the failure mode you care about, and only escalate when it doesn't. Bloating every eval to an LLM judge (or human review) burns budget without improving signal.

03

"Shipping Fiction"

Ungrounded, agent-generated content — an AI-written blog post with no evidence behind its claims — is effectively shipping fiction. The room tied this back to evaluation: without a grounding step and a grader that checks it, agents confidently publish output nobody can vouch for.

Speaker 03

Agents vs. Workflows

Agents vs. Workflows

A discussion that veered off the slides into one of the sharpest exchanges of the night: the difference between deterministic workflows and autonomous agents, and where each belongs in a production system.

n8nDeterministic workflowsAgentsTools
01

Workflows Are Deterministic

A workflow (e.g. built in n8n) takes a defined path: fixed steps, predictable order, easy to test and retry. If you know the path ahead of time, a workflow is the right tool — determinism is a feature, not a limitation.

02

Agents Figure Out The Path

An agent takes a goal plus a set of tools and works out the path at runtime. That flexibility is a cost too: unpredictable behaviour, harder eval, harder debugging. The room's consensus — keep the path deterministic where it can be, and let agents loose only where replanning earns its keep.
